# 风格分析协议

在执行风格聚合前，按照本协议生成逐图观察结果。目标是提取可迁移的视觉系统，而不是描述图片中画了什么。

## 1. 建立样本集

为每个文件记录：

- 稳定的 `image_id`；
- 本地文件的来源路径和 SHA-256；
- 文件是否可读取，尺寸是否足以判断；
- 如果是完全重复或近似重复图，记录 `duplicate_of`；
- 导致某类特征无法判断的限制。

只有可读取且不重复的图片才计入分母。不能因为某张图片与多数图片不一致就将其删除。

## 2. 分离内容与风格

| 保留为可迁移风格 | 作为内容剥离 |
|---|---|
| 边缘软硬、轮廓粗细、线条节奏 | 人物、具名角色、物种 |
| 色相关系、饱和度范围、明度结构 | 具体服装、道具、建筑 |
| 漫射或方向性光照规律 | 确切时间、地点、事件、动作 |
| 表面颗粒、半透明感、笔触或渲染纹理 | IP 标志、Logo、文字内容 |
| 几何或有机的造型倾向 | 具体姿势或关系身份 |
| 景深压缩、留白倾向、焦点层级 | 确切拍摄主体或场景叙事 |

用一个完全无关的新主题替换画面中的全部主体，以此测试每个候选特征。如果替换后描述不再成立，则它属于内容，必须删除或抽象化。

错误示例：`城堡旁的粉发少女`、`猫一样的眼睛`、`王子服装`。

正确示例：`低饱和冷色基底搭配少量暖色点缀`、`柔和边缘过渡`、`细长且逐渐收尖的造型`。

## 3. 按类别观察

只记录能够从当前图片中明确判断的类别：

- `line_edge`：轮廓是否存在、粗细、连续性、硬边或软边过渡。
- `palette`：色相族关系、饱和度、冷暖平衡、点缀色策略。
- `value_contrast`：高调或低调、对比范围、阴影分离方式。
- `lighting`：方向性、漫射程度、辉光、轮廓光和高光表现。
- `material_texture`：颗粒、纸张、颜料、塑料、玻璃、织物式渲染和表面粗糙度。
- `rendering_modeling`：平涂、赛璐璐、绘画式或体积式塑造、颜色混合、细节分布。
- `shape_language`：与主体无关的圆润、尖锐、收尖、厚重或纤细倾向。
- `surface_effects`：发光、粒子、光晕、色差、暗角、噪点。
- `spatial_grammar`：可迁移的景深压缩、焦点层级、画面密度、留白和裁切方式。

每条观察必须是原子级特征。如果柔和度、配色和光照可以独立变化，应将“柔和粉彩梦幻光影”拆分成多条特征。

## 4. 归一化特征 ID

聚合前先合并同义词、拆分相反概念。特征 ID 使用稳定的英文小写下划线格式，展示标签使用简洁中文。

示例：

- `soft_edge_transitions` — 柔和边缘过渡
- `low_saturation_palette` — 低饱和配色
- `diffuse_wrap_light` — 漫射包裹光
- `uniform_hard_outline` — 均匀硬轮廓

只有当两条观察描述同一种可见属性时，才能共用一个 ID。不能直接合并“梦幻”“浪漫”“高级”等宽泛氛围词，必须先说明产生这种氛围的可见机制。

## 5. 记录正向与负向证据

- `positive`：能够明确看到该特征存在。
- `negative`：能够确认该特征不存在，或能看到稳定且互斥的相反特征。
- 无法判断：不在该图片下记录此特征。无法判断永远不能计为负向证据。

负向标签应描述生成器必须压制的可见特征，例如“均匀硬黑轮廓”或“镜面塑料高光”。不能写“不好看”“不高级”等模糊词，也不能加入与画风无关的内容禁令。

用户明确提出的禁止项应写入顶层 `explicit_negatives`，不能伪装成图片观察结果。

## 6. 应用频次门控

对于 `N` 张有效不重复图片：

```text
minimum_count = ceil(0.60 × N)
prevalence = images_supporting_feature / N
```

示例：N=3 → 2，N=4 → 3，N=5 → 3，N=8 → 5，N=10 → 6。

同一特征在每张图片中最多计数一次。低于门槛的特征保留在 `excluded_features` 中，便于用户审查哪些内容被过滤。

## 7. 最终语义检查

生成最终 Prompt 前：

- 扫描已通过的风格基因，发现主体名称时必须改写或删除；
- 确保每个负特征都是可控制的视觉边界；
- 检查正向和负向基因是否相互矛盾；
- 区分图片直接证据与用户明确要求；
- 当样本较少、图片压缩严重、使用拼贴排版或来源不一致导致可信度降低时，必须明确说明。
